# 中文解说稿写法

解说稿决定成片的三件事：**配音的听感**（语速、停顿、表情）、**字幕的断句**（标点即断句）、
**画面的卡点**（词级时间戳）。

## 结构

一帧一段，每段一个小节，`## Line N — 标签 (Frame N)`，正文缩进四格或一个 Tab。工具按帧号对齐。

```md
## Line 3 — 真动手 (Frame 3)

**Time:** 20 – 33s
**Delivery:** "真的动手"是题眼，重读；排比逐步加强。rate +3% · pitch +4Hz

    和只会聊天的 AI 不一样，Pi 是真的动手。每一次读取、每一条命令、每一处修改，都摆在你眼前——不藏着，也不烦你。
```

`**Delivery:**` 行里的 `rate ±N%` 和 `pitch ±NHz` 会被配音脚本读取并逐句应用，这是在不换音色的
前提下最有效的"加表情"手段：

| 位置 | 建议 | 听感 |
| --- | --- | --- |
| 开场钩子 | rate -4% · pitch +4Hz | 放慢、挑起来，像在提问 |
| 优点/清单段 | rate +3~4% · pitch +2~4Hz | 干脆、有推进感 |
| 收尾 CTA | rate -4% · pitch -2Hz | 压低、一字一顿，落得住 |
| 说明性长句 | rate 0 · pitch 0 | 求清楚，不加戏 |

## 句式

- 每帧 1–3 句，每句 **8–20 字**；长句用逗号切成小句——TTS 会在标点处自然换气，字幕也在这里断行
- 一帧只讲一件事；帧与帧之间有推进（是什么 → 会做什么 → 好在哪 → 用在哪 → 怎么开始）
- 开场用一个**认知缺口**（"如果 AI 不只是给你出主意——"），结尾回扣它
- 少用书面连接词（"从而""进而""值得注意的是"），多用人话

**强**（具体、有画面）：
> 给它一个目标、一个目录，它会读文件、跑命令、改代码，一步一步把任务做完。

**弱**（像念文档、无节奏）：
> 该工具支持文件读取、命令执行与代码编辑等多项能力，能够完成多步骤任务。

## 多音字与易错读

TTS 会在下列位置出错，**写稿时直接换词**，比事后一遍遍重试便宜：

| 高危字 | 问题 | 换成 |
| --- | --- | --- |
| 分**叉** | 读成 chā（应为 chà） | 另开一条 / 岔开 |
| 长**成** | zhǎng/cháng 摇摆 | 变成 / 变成…的样子 |
| **干**活、干完 | gān/gàn 摇摆 | 做 / 做完 |
| **调** | 读成 diào（应为 tiáo） | 定 / 设定 / 改 |
| **行**（一行命令 / 银行） | háng/xíng | 保留（常见词，通常正确）；单独出现时改写 |
| 差、发、藏、系 | 语境依赖 | 换成单音词 |

**校验方法**：`scripts/verify_pronunciation.py` 用本地 whisper 把配音转写回文字，与脚本逐句比对。
它会一并报出 whisper 自己的同音误判（会话/绘画、事/是、只会/指挥），所以**只改两边都指得通的真错**——
判断标准：听感上是否会造成歧义，而不是转写文本是否字面相同。

## 字数和时长

中文播报约 **4.2–4.8 字/秒**（rate +0%）。一帧的目标时长 ≈ `字数 ÷ 4.5 + 换气 1.0s`。
例：一句 45 字 → 约 11 秒。按这个估分镜，能避免"画面写到一半发现时长不够/太空"。

全片时长 = Σ(每帧语音时长 + tail)。**连贯性优先**：常规帧 tail 0.9s（句间约 1.4s 换气），
只在段落转场（1.8s）和结尾 CTA（5s+）才留大白。宁可成片短 15 秒，也别让人听着像一句一停顿。

## 屏幕文案（与解说稿分开）

画面上的字**不是字幕的复印件**。每帧准备 1–3 个短元素：

- 关键词/术语（`会话会分身`、`模型自由`）
- 数据/公式（`读 + 改 = Pi 的主场`、`3 / 3 完成`）
- 真实命令/代码（`curl -fsSL https://pi.dev/install.sh | sh`）——这些是内容，不算旁白重复

不写：整句旁白、导航条、页脚、装饰性英文小字。
